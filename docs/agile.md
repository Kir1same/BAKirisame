# 敏捷开发计划

## 产品愿景

做一个面向断箭玩家的 QQ 数据分析助手：少输入、快响应、结论清楚，既能查基础数据，也能给出可解释的战绩和环境分析。

## Sprint 0：项目成型

目标：跑通技术路线，形成可部署骨架。

交付物：

- QQ 官方机器人项目结构。
- 配置、启动、测试说明。
- 命令解析和 Mock 数据分析。
- 数据层接口，等待真实断箭 API 接入。

验收标准：

- `pytest` 通过。
- `.env` 填入 QQ 凭据后可启动机器人进程。
- `/help`、`/player`、`/meta`、`/unit` 有稳定文本输出。

## Sprint 1：真实数据接入

目标：接入断箭官方 API 或获得授权的数据接口。

用户故事：

- 作为玩家，我可以输入 `/player <玩家>` 查看胜率、ELO、近期状态。
- 作为玩家，我可以输入 `/unit <单位>` 查看胜率、登场率和简短评价。
- 作为群友，我可以输入 `/meta` 查看当前版本强势阵营、单位和地图趋势。

验收标准：

- 数据接口错误时有友好降级。
- 响应时间和限流策略可观测。
- 不泄露 API Key、玩家隐私或未授权数据。

## Sprint 2：分析能力

目标：从“查数据”升级到“解释数据”。

用户故事：

- 作为玩家，我能看到最近 20 场和总战绩的差异。
- 作为玩家，我能获得一句简洁的改进建议。
- 作为管理员，我能配置群内默认查询语言和冷却时间。

## 风险清单

- 断箭官方 API 是否公开、是否需要授权、频率限制是多少，目前还需要确认。
- QQ 正式环境可能要求固定公网 IP、IP 白名单和审核。
- 主动推送能力受限，机器人应优先做被动回复。
- 群内高频查询需要缓存和冷却，避免触发平台频控。
